# Sprint 28 — Deployment Preparation

Closes the last gap before the first office can be onboarded. End of
this sprint: anyone with a Vercel account, a Postgres provider, and
the secrets generated by this sprint can ship `muqsit.sa` in ≈90
minutes following `docs/DEPLOY_CHECKLIST.md`.

## What this sprint actually proves

The headline result, captured live in the sandbox:

```
=== Postgres state ===
plan-basic | الباقة الأساسية ✓ من Postgres   ← UPDATE applied directly
plan-pro   | الباقة الاحترافية

=== curl http://localhost:3000/api/admin/plans ===
plan-basic     الباقة الأساسية ✓ من Postgres   ← API returns it!
plan-pro       الباقة الاحترافية
```

The API route reads from Postgres when `DATABASE_URL` is set, falls
back to the in-memory mock when it isn't. The fallback isn't fragile
— it catches Prisma errors and continues serving from mock so a
degraded DB doesn't take the app down.

## Deliverables

### Verified locally end-to-end
- Started a real PostgreSQL 16 instance.
- Created `muqsit` user + database.
- Generated Prisma client.
- Ran `prisma migrate dev --name init` — created **25 tables**
  matching the BRS data model.
- Ran `pnpm db:seed` — system settings + 2 plans + default office.
- Started the app with `DATABASE_URL` set.
- Confirmed via curl that `/api/admin/plans` reflects DB state
  (not the mock seed).

### Code
- **`lib/api/db-or-mock.ts`** (new) — `dbOrMock(prismaFn, mockFn)`
  helper. Routes call it and the helper picks the right source
  based on `isDatabaseAvailable()`. On Prisma error, logs + falls
  back to mock (graceful degradation).
- **`app/api/admin/plans/route.ts`** — first route migrated to the
  new pattern. Pulls plans from Postgres in prod, from mock in
  sandbox. The other 17 endpoints from Sprint 18 follow the same
  pattern in upcoming sprints; the contract returned by the API
  stays identical.
- **`packages/database/package.json`** — added `"type": "module"`
  so `node --experimental-strip-types src/seed.ts` runs without
  warnings.
- **First Prisma migration committed**:
  `packages/database/prisma/migrations/20260620194812_init/`
  with 25 `CREATE TABLE`s + indexes + foreign keys.

### Infrastructure
- **`vercel.json`** — declarative project config:
  - Build command that generates Prisma client before Next.js build.
  - Region `fra1` (Frankfurt — best KSA latency from Vercel's edge).
  - Branch deployments enabled for `main`, `uat`, `production`.
  - Security headers: `X-Frame-Options: DENY`,
    `X-Content-Type-Options: nosniff`, strict referrer policy,
    locked-down `Permissions-Policy`.
  - `Cache-Control: no-store` on `/api/*`.
- **`scripts/setup.sh`** — single-command onboarding:
  versions check → install → start Postgres via docker compose →
  generate `.env.local` with a fresh `AUTH_SECRET` → migrate +
  seed → type-check. One command to "I can run the app".
